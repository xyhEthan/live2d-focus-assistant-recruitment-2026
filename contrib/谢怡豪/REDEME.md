# 地牢探险 · Dungeon Quest

> 一个纯 Python 实现的回合制文字冒险游戏。你是受雇深入诅咒地牢、
> 夺回传说圣物「星之碎片」的冒险者。探索随机生成的地牢、与怪物
> 战斗、管理背包与金币、击败深渊领主并带圣物脱身。


---

## 1. 项目名称与目的

- **名称**：地牢探险 · Dungeon Quest
- **目的**：用一个**真正可运行、含循环 / 条件 / 数据处理逻辑**的
  Python 程序，演示一个完整的小型游戏循环——从角色创建、随机地图
  生成、回合制战斗、物品 / 金币经济、到 JSON 存档与读档、胜负判定。
- 它**不是**仅打印固定文本或做基本算术的 demo：玩家每一次输入都会
  改变游戏状态（移动、攻击、防御、用道具、逃跑、保存），背后是
  实打实的状态机与随机数驱动的数据流。

## 2. 主要功能与典型使用流程

### 主要功能
- **三大职业**：战士（高血防）、法师（高攻低血）、盗贼（高敏运，易闪避暴击），起始属性不同，影响策略。
- **随机地牢地图**：5×5 网格，每局随机生成；起点固定为空房，终点为 Boss 房；含空房、怪物、宝箱、陷阱、商店、篝火、Boss 七种房间。
- **回合制战斗**：攻击 / 防御（减伤）/ 使用物品 / 逃跑；含暴击、闪避、攻击波动；防御与闪避由敏捷属性驱动。
- **升级系统**：击杀获得金币与经验，经验满足阈值即升级（生命上限+15、攻击+3、防御+2、回满血）。
- **物品与经济**：生命药水（治疗）、力量卷轴（永久+攻击）、铁甲护符（永久+防御）、星之碎片（通关钥匙）；可在商店花金币购买。
- **存档 / 读档**：进度以 JSON 写入用户主目录 `~/.dungeon_quest_save.json`，重启后可选择继续；通关或死亡自动清档。
- **楼层难度**：怪物随楼层线性增强（HP/ATK/DEF 按楼层缩放）。
- **地图视图**：随时查看探索进度（★玩家、B Boss、?未探索、.已清理）。

### 典型使用流程
1. 运行 `python app.py`，若存在存档会询问是否继续。
2. 输入角色名并选择职业（战士 / 法师 / 盗贼）。
3. 在主菜单选择移动（上下左右）探索房间；进入未清理房间触发事件。
4. 遇怪进入回合制战斗，选攻击 / 防御 / 物品 / 逃跑；胜利得金币与经验。
5. 宝箱给金币或道具；陷阱扣血（可被敏捷躲过）；商店买卖道具；篝火回血。
6. 随时 `s` 存档、`m` 看地图、`l` 查看并使用背包。
7. 到达 Boss 房击败深渊领主并拥有星之碎片即**通关**；血量归零即**失败**。

## 3. 环境要求、安装与运行命令

### 环境要求
- **Python**：3.8+（使用 `dataclasses` 默认值字段、`f-strings`、类型注解）。
- **第三方依赖**：**无**。仅使用标准库 `random`、`json`、`os`、`sys`、`dataclasses`、`typing`。
- **操作系统**：跨平台（Windows / macOS / Linux 均可），需命令行交互。

### 安装与运行
```bash

cd live2d-focus-assistant-recruitment-2026/contrib/<你的目录>

# 2. 无需安装任何依赖（requirements.txt 为空，仅依赖标准库）
#    如需显式安装可执行：pip install -r requirements.txt

# 3. 运行游戏
python app.py
```

## 6. 已知限制或未完成的想法

- **单层循环**：当前实现到「击败 Boss + 持星之碎片即通关」；
  原本设计「楼梯下楼进入下一层」的多层结构尚未接入主循环（楼层
  变量 `floor` 已就绪、怪物楼层缩放已实现，但通关即结束）。
- **战斗输入耗尽处理**：当通过管道喂入固定输入且战斗回合数超出
  预期时，会读到 `EOF` 并安全退出；交互式游玩不受影响，但自动化
  重放需要自适应驱动（已用 `smoke_driver.py` 解决）。
- **没有彩色输出 / 终端控制**：为保证跨平台与零依赖，未使用
  `colorama` 等 ANSI 库；emoji 仅作点缀，纯文本环境也能游玩。
- **存档无加密 / 无校验**：JSON 明文存储，便于检查与调试；若用于
  多人对战场景需加完整性校验（当前单人本地游戏不必要）。
- **未实现的想法**：随机事件房间（岔路选择）、装备耐久、状态Buff
  （中毒 / 燃烧）、多结局分支——均为后续可扩展点。
